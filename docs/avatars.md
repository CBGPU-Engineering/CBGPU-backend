# Profile pictures and default avatars

The database is the only source of truth. Clients render `avatarUrl` exactly as received and never build
avatar-provider URLs themselves, so style and version cannot drift between web, mobile, admin, e-mail and push.

## Response shape

```json
{ "id": "…", "name": "…", "avatarUrl": "https://…", "profileImageUrl": "https://…" | null }
```

| Field | Meaning |
| --- | --- |
| `avatarUrl` | What to display. Never null. |
| `profileImageUrl` | The photo the user uploaded, or `null`. Use it only to decide whether to show "Delete photo". |

## URL rule

1. The user has an uploaded photo (`profiles.avatar_url` is not blank) → that URL.
2. Otherwise → `<base_url>/<version>/<style>/<format>?seed=<avatar_seed>&size=<size>`, which by default is
   `https://api.dicebear.com/9.x/thumbs/png?seed=<avatar_seed>&size=256`.

Deleting the photo clears `avatar_url`; the same `avatar_seed` then produces the same default avatar again.

## Seed

`profiles.avatar_seed` is a random UUID generated by the database (`gen_random_uuid()`) when the profile row is
created. It is not derived from the name, e-mail, student number, school or account id, so nothing personal is
sent to the avatar provider. It never changes: a trigger rejects any update (`AVATAR_SEED_IMMUTABLE`) and replaces a
seed supplied by a client role on insert. Migrating existing users happens in one `ADD COLUMN … DEFAULT
gen_random_uuid()` statement, which gives every row its own value without firing row triggers.

## Configuration (one place)

`public.avatar_settings` has a single row: `base_url`, `version`, `style`, `format`, `size`. Values are validated by
check constraints (https base URL, `^\d+\.x$` version, lowercase style, `png|svg|jpg|webp|avif`, size 16–512).
Only `service_role`/the database owner can change it; `anon` and `authenticated` cannot read or write it.

```sql
update public.avatar_settings set style = 'thumbs', version = '9.x', size = 256;   -- every client follows
update public.avatar_settings set base_url = 'https://cbgpu.com/api/avatars';      -- switch to an own proxy
```

## Where it is exposed

| Surface | How |
| --- | --- |
| Any PostgREST query on `profiles` | computed columns `display_avatar_url` and `profile_image_url` (`select=id,full_name,display_avatar_url`) |
| Canonical user card | view `public.user_cards` → `{id,name,avatarUrl,profileImageUrl}`; runs as the caller, so profile RLS (including school boundaries) is unchanged |
| School-scoped screens | `public.cbgpu_study_member_cards(uuid[])` wraps the existing `cbgpu_study_member_profiles` and only adds the avatar fields |
| Community / DM / members / nominations / GPU admin JSON | `avatarUrl` and `profileImageUrl` are added by wrappers around the original builders (see `avatars-surfaces.md`) |
| Another school's person (name hidden) | `public.cbgpu_avatar_urls(uuid[])` returns only `{id, avatarUrl}`; names, student numbers and schools stay behind their RLS |
| Server-rendered output (e-mail, OG image, push) | call `public.cbgpu_default_avatar_url(seed)` / read `user_cards` with the service role; do not rebuild the URL |

## Privacy and availability

Rendering the default avatar from `api.dicebear.com` sends the viewer's IP address and user agent to a third party
and makes avatars depend on its uptime. The seed itself carries no personal data. The recommended hardening is a
same-origin proxy/cache. The web app ships one at `/api/avatars/<version>/<style>/<format>`: point `avatar_settings.base_url` at `https://cbgpu.com/api/avatars` (no client change needed). See `avatars-rollout.md`.

## Photo URL rule

`profiles.avatar_url` may only be `NULL` or `https://cbgpu.com/backend/storage/v1/object/public/avatars/<own id>/avatar.(jpg|jpeg|png|webp)[?v=<digits>]` (check constraint `profiles_avatar_url_storage_chk`). Change the host in that constraint if the storage URL ever moves.
